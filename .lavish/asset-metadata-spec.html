Storefront metadata enrichment

When an asset in damson has (or can find) a storefront listing — Unity Asset Store, Sketchfab, itch.io, or any URL — fetch its public metadata: description, publisher, licence, price, store URL, and cover image. Two entry points: search by name (present match candidates, user picks one) and fetch from a user-supplied source URL. Annotate anything, and answer the queued questions at the bottom.

3Chosen approach — C: layered fetchers + import auto-enrichment

Decided: Approach C — everything in the layered, adapter-based design (A), plus automatic enrichment when an asset is imported. Adapters in v1: Unity Asset Store (GraphQL + Coveo search), Sketchfab (official API), itch.io (page scrape incl. licence row) + itch.io name search (HTML results scrape). Fab stays URL-only until Epic ships an API.
  • Generic OG/JSON-LD scraper as the base — the fallback for every URL, and the whole answer for unknown stores. Store adapters layer on top, keyed by URL host, each degrading to the generic scraper on failure.
  • Unity data source: unofficial GraphQL primary (version, screenshots, publisher, price, entitlement/licence type) with OG/JSON-LD page-scrape fallback.
  • Apply semantics — fill blanks, confirm overwrites: fetched values land automatically in fields that are empty; anything that would overwrite an existing value is listed for explicit confirmation. Human-reviewed data is never silently clobbered.
  • Cover image becomes the asset thumbnail via the existing content-addressed thumb pipeline — set automatically when no thumbnail exists, otherwise offered as an overwrite; rescan can regenerate the extracted one.
  • Auto-enrich on import: a metadata stage in the import pipeline searches by the derived asset name and applies the top hit only on a high-confidence normalised-title match; otherwise it stores the candidates for one-click review and applies nothing. Fills blank fields only, flags the asset NeedsReview. Raw fetched payloads always persist to SourceMetadataJSON.
  • Auto-enrich is a per-library setting — a new LibrarySettings toggle alongside PreviewsEnabled etc., default on; the pipeline stage is skipped when off. Manual fetch/search always available regardless.

4How it works

Flow 1 — search by name

User clicks "Find listing" in the asset detail panel (pre-filled with asset name, editable)
→
GET /api/metadata/search fans out to Unity Coveo + Sketchfab API (+ itch HTML) with a short timeout; merges candidates
→
Match picker dialog shows candidates: cover, title, publisher, store, price
→
User picks one → its URL becomes the source URL → continues into Flow 2

Flow 2 — fetch from source URL

POST /api/assets/:id/metadata/fetch — host-matched adapter runs (Unity GraphQL / Sketchfab API / itch scrape), else generic OG/JSON-LD
→
Blank fields fill immediately; raw blob stored in SourceMetadataJSON; response lists any would-overwrite fields
→
User confirms overwrites only — name, description, cover → thumbnail, licence → licence flow
→
Apply endpoint persists confirmed overwrites, writes audit entries, respects reviewed data

Flow 3 — auto-enrich on import

New pipeline stage after thumbnailing: search stores by the derived asset name
→
Confidence gate — only a match whose normalised title closely matches the asset name is used (see Q6)
→
Fill blanks only — description, source URL, licence, thumbnail-if-none; never overwrites. Candidates + raw payload kept in SourceMetadataJSON
→
Flag NeedsReview + SSE stage events; enrichment failure never fails the import
Auto-enrich caveats (accepted with C): filename-derived names are noisy (com.demigiant.dotween-1.2), so the confidence gate matters; and every upload now makes outbound requests to unofficial endpoints — mitigated by per-host rate limiting, response caching, and the confidence gate short-circuiting weak matches before any detail fetch.

Detail panel + match picker (sketch)

A "Find listing" action beside the existing Source URL field; picking a match runs the fetch and opens the field-confirm view.

Security note (spec'd in): the server fetches user-supplied URLs, so the fetcher must block private/loopback IPs (SSRF), cap response size and redirects, enforce timeouts, and validate image content types before storing covers. validateSourceURL covers scheme checks today; the rest is new.
ToS posture: Unity's GraphQL + Coveo endpoints are undocumented and unsanctioned but stable for years in community tools. Mitigations: user-triggered only, per-host rate limiting, cached responses in SourceMetadataJSON, and automatic degrade to the OG/JSON-LD page scrape if the endpoint breaks.

1
Fetcher core + generic scraper

internal/services/metadata/: SSRF-guarded HTTP client, OG/JSON-LD parser (golang.org/x/net/html, already an indirect dep), normalised Metadata struct, host→adapter registry. Unit tests on fixture HTML.

Store adapters

Unity (GraphQL batch + CSRF bootstrap, fallback to page scrape), Sketchfab (Data API v3), itch.io (JSON-LD + info-table licence row). Each degrades to the generic scraper on failure.

POST /assets/:id/metadata/fetch (fills blanks, persists raw blob to SourceMetadataJSON, returns would-overwrite fields), apply endpoint for confirmed overwrites reusing patch/licence/thumbnail paths, audit entries, source_metadata in the detail view.

4

GET /api/metadata/search?q= fanning out to Unity Coveo + Sketchfab API + itch.io HTML results, merged candidate list with store provenance.

5
Frontend

"Find listing" + "Fetch" in AssetDetailPanel, match-picker dialog (new composition from existing Dialog primitives), overwrite-confirm view, query/mutation hooks.

6
Import pipeline auto-enrichment

New metadata stage after thumbnailing, gated on a new per-library LibrarySettings toggle (default on): name search → high-confidence gate → fill blanks → NeedsReview, SSE stage events, failure never fails the import, per-host rate limiter shared with the manual endpoints. Settings UI checkbox alongside the existing library toggles.

7
Review surface polish

Show auto-enriched provenance in the detail panel (which store, when, confidence), surface stored match candidates for one-click correction when the gate picked wrong or abstained.
