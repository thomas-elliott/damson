# `dmsn` — an AXI-native CLI for damson

**Status:** implemented (2026-08-01).
**Relationship to the Unity slice:** this spec was split out of
[`2026-08-01-unity-local-cache-import.md`](2026-08-01-unity-local-cache-import.md), taking its
stage 1 (personal access tokens) and stage 4 (the CLI binary) wholesale. That spec now depends on
this one and keeps only the Unity-specific work; it has been amended accordingly, so the two no
longer overlap.

## Problem

Every path into damson goes through a browser. `POST /api/imports` is driven by the SPA's
drag-and-drop, one file per request; there is no way to bulk-load a directory tree, no way to script
curation, and no way for an agent to touch a library at all — `auth.Middleware` accepts a 1 h local
JWT or an IdP bearer, both of which need a human at a browser.

The API itself is already complete enough: sixty-odd routes cover assets, versions, tags,
collections, projects, licences, imports, search and settings. What is missing is a credential that
survives unattended use, and a client that speaks it.

That client's heaviest user is an agent, not a person. The tasks are shaped like "tag every Synty
asset", "put the character packs in a collection", "which imports failed" — read a lot, mutate a
little, repeat. So the CLI is built to the [AXI principles](https://axi.md/), whose premise is that
token budget is a first-class constraint and that a well-shaped CLI beats an MCP server on cost,
latency *and* reliability.

## Chosen approach

**A single Go binary, `dmsn`, at `cmd/dmsn`** — same module, stdlib `flag`, no new dependency —
authenticated by a new personal-access-token credential and shaped end to end by the ten AXI
principles.

Three placements carry most of the design:

- **TOON output by default, JSON on request.** The whole AXI contract (encoding, field projection,
  truncation, `help[]` disclosure, the error envelope) lives in one pure-Go render layer with no
  I/O and no gin, so it is unit-testable in isolation and every command inherits it.
- **A folder becomes one asset by being zipped client-side.** `.zip` is already a first-class
  package kind on `POST /api/imports`; `extract.ZipExtractor` writes `asset_files` with relative
  paths preserved, picks a cover, thumbnails and enqueues previews. The upload path needs no server
  change at all.
- **Ambiguity fails loud rather than defaulting.** AXI forbids interactive prompts, so
  `dmsn upload ./SomeFolder` — where "one asset" and "a folder of assets" are equally plausible —
  exits 2 and hands back both concrete commands instead of guessing.

### The ten principles, mapped

| # | Principle | What `dmsn` does |
|---|---|---|
| 1 | Token-efficient output | TOON by default from a new `internal/toon` encoder. `--json` escape hatch. |
| 2 | Minimal default schemas | `assets` defaults to `id,name,publisher,needs_review`. Wider output is opt-in via `--fields`, which validates and exits 2 on an unknown name. |
| 3 | Content truncation | Descriptions and licence text clipped to 400 chars with `(truncated, N chars total — use --full)`. |
| 4 | Pre-computed aggregates | `total:` and `shown:` on every list (the handlers already return `total`). `GET /api/overview` collapses the home view into one round trip. `upload` prints `2 imported, 1 failed, 1 skipped`. |
| 5 | Definitive empty states | Never silent: `assets[]: no assets match tag_path=Characters (412 assets in library)`. |
| 6 | Structured errors & exit codes | Errors as a TOON `error:` block on **stdout**, `code` lifted from the HTTP status and the server's `{"error": msg}` body. `0` success, `1` failure, `2` usage. Destructive verbs require `--yes`. Mutations idempotent where the API allows, reporting `changed`. |
| 7 | Ambient context | `dmsn setup` writes a Claude Code skill plus an optional SessionStart hook. |
| 8 | Content first | Bare `dmsn` prints version, its own resolved path with `~`, one sentence, then live library state. |
| 9 | Contextual disclosure | A `help[N]:` block after every output with concrete next commands; real flags literal, runtime values as `<id>`. `--no-help` suppresses. |
| 10 | Consistent help | `--help` on every subcommand, one screen, exits 0. |

### Command surface

Global flags on every command: `--server --token --json --fields --full --no-help --quiet --timeout`.

| Command | Behaviour · endpoint |
|---|---|
| `dmsn` | Home view — `GET /api/overview` (new) |
| `login --server URL --token …` | Verifies via `GET /api/me` before writing `config.json` (0600). Never echoes the secret. Also reads `DAMSON_TOKEN` / `DAMSON_SERVER`. |
| `logout` · `whoami` | Clears config · prints user, library, token prefix, scope, expiry |
| `upload <path>… [--as asset\|assets]` | `POST /api/imports/preflight` (new) then `POST /api/imports`. Flags: `--skip-existing`, `--asset-id N`, `--store-version`, `--concurrency 2`, `--dry-run`, `--wait` |
| `assets [filters]` | `GET /api/assets` — `--q --tag --collection --project --publisher --store --package-kind --needs-review --updates-available --released-after --sort --limit --offset` |
| `asset <id>` | `GET /api/assets/:id`, flattened |
| `asset edit <id> [--name …]` | `PATCH /api/assets/:id` — name, description, source-url and all 13 storefront fields. `--clear FIELD` nulls one. |
| `asset review\|unreview <id>` | `POST /api/assets/:id/review` — idempotent, reports `changed` |
| `asset rm <id> --yes` | `DELETE /api/assets/:id` |
| `asset tag <id> <path>…` · `asset untag <id> <path>…` | `POST` / `DELETE /api/assets/:id/tags` |
| `tags` · `tag new <path>` · `tag rm <path>` | `GET`/`POST`/`DELETE /api/tags` |
| `collections` · `collection <id>` · `collection new\|edit\|rm` | The `/api/collections` set |
| `collection add\|remove <id> --assets 1,2,3` | `POST /api/assets/bulk` |
| `bulk tag\|untag\|review\|unreview\|rm --assets …` | `POST /api/assets/bulk`, returns `affected` |
| `imports [--stage …]` · `import retry <id>` | `GET /api/imports` · `POST /api/imports/:id/retry` |
| `setup [--project] [--no-hook]` | Writes the Claude Code skill + optional SessionStart hook |
| `version` | Version, commit, server version from `GET /api/health` |

### Upload semantics

A *file* is unambiguous: one asset, exactly today's behaviour. A *directory* is not, so `--as` is
**required** for one, and the usage error carries both templates:

```
$ dmsn upload ~/Packs/RPG\ Builder
error:
  code: usage
  message: "~/Packs/RPG Builder is a directory; --as is required"
help[2]:
  dmsn upload "~/Packs/RPG Builder" --as asset
  dmsn upload "~/Packs/RPG Builder" --as assets
$ echo $?
2
```

- `--as asset` — the directory is zipped to a temp file (sorted entries, deflate) and posted as
  `<FolderName>.zip`. Known length gives a real progress figure, a pre-upload size check against
  `max_upload_bytes`, and cheap retry-whole-file.
- `--as assets` — the same rule applied to each direct child: a file uploads as-is, a subdirectory
  is zipped.

### How `--skip-existing` divides between the two specs

The Unity spec's preflight keys off `(source_kind, source_relative_path, source_size_bytes)`
persisted on the version row — columns *its* stage 2 adds. Without them the server can still answer
the weaker but useful question, *do you already hold something by this name?*, via the existing
`imports.MatchAssetByName`. That is the same normalised title matcher `POST /api/imports` already
uses to return `suggested_match` after an upload; preflight is that matcher asked before the bytes
move.

So the endpoint lands here with two statuses and the Unity slice widens it to four. Same route, same
request shape, additive response. Results correlate to the request by `index`; entry count is capped.

```
POST /api/imports/preflight
{"entries":[{"filename":"RPG Builder.unitypackage","size_bytes":184320112}]}

→ {"results":[{"index":0,"status":"name_match","asset_id":511,
               "asset_name":"RPG Builder","version_count":2}]}
```

| status | Meaning | Owned by |
|---|---|---|
| `new` | No name match — upload as a new asset | this spec |
| `name_match` | A normalised title match exists | this spec |
| `already_imported` | Path + size both match | Unity slice |
| `updated` | Path matches, size differs → new version of `asset_id` | Unity slice |

Name-only matching cannot distinguish "you already have this exact file" from "this is a newer
version of an asset you hold" — both read as `name_match`. `--skip-existing` is therefore
deliberately conservative: it skips anything with a name match, and its help text says so.

### Rejected alternatives, and why

- **A new multi-file upload endpoint** for folder-as-one-asset. More faithful — no synthesised
  archive, no double-store — but it is a second version-writing path running parallel to the
  extractor: file rows, thumbnail selection, size caps, size accounting, and one very long multipart
  request with no resumability. Weeks of work to land where a client-side zip lands immediately.
  The cost accepted instead: temp disk equal to the compressed folder, and a retained "original
  package" that is a CLI-synthesised zip the user has no copy of.
- **Cobra or urfave/cli.** `go mod tidy` is CI-enforced and the dependency buys little here —
  stdlib `flag` already exits 2 on an unknown flag, which is precisely principle 6's requirement.
- **Composing the home view from existing routes.** Five requests (`/me`, `/assets?limit=1` for
  `total`, `/collections`, `/tags`, `/imports`), three of which transfer payloads only to discard
  them — on every agent session start, since the ambient hook runs every time.
- **Tokens with no scopes**, as the Unity spec had them. Fine when the only verb was upload; wrong
  once the same credential can delete assets and rewrite metadata, and the point of principle 7 is
  handing the binary to an agent.
- **An MCP server.** AXI's whole argument is that this CLI is the cheaper interface — 79 K vs 185 K
  tokens per task on their benchmark.
- **`damsonctl` as the binary name.** Considered and rejected in favour of `dmsn`: an agent types
  the binary name on every single call, so 9 characters against 4 is a measurable slice of exactly
  the budget principle 1 exists to protect. The server binary keeps the name `damson`, so the
  Dockerfile, k8s manifests and release pipeline are untouched. The config directory stays
  `damson/` — that names the product, not the client.

## Task breakdown

Ordered stages, roughly one commit each.

### Stage 1 — Personal access tokens, server side

Local mode issues 1 h JWTs (`auth.LocalTokenTTL`); OIDC mode validates IdP bearers. Neither suits an
unattended client, so this is new mechanism rather than a tweak.

- Migration `020_api_tokens.sql` — `api_tokens`: `user_id` (not null, index), `library_id` (not
  null), `label`, `token_hash` (not null, unique), `prefix`, `scope` (not null, default `write`),
  `created_at`, `last_used_at`, `expires_at`, `revoked_at`. Matching `models.APIToken` with GORM
  tags. (`019` is taken by `019_asset_metadata_fields.sql`; the Unity spec's `020_import_source.sql`
  becomes `021`.)
- Secret format `damson_pat_<32 random bytes, base64url>`, stored as a plain SHA-256 hex digest —
  **not** bcrypt. The secret is high-entropy, so a slow KDF buys nothing and a fast digest allows a
  direct indexed lookup.
- `auth.Middleware` gains a `TokenAuthenticator` parameter (nil disables). The branch sits ahead of
  `a.Authenticate`, keyed on the `damson_pat_` prefix, so it behaves identically in both auth modes.
  On success it sets `CurrentLibraryID` to the token's library **on the request-scoped user copy
  only** — so `requireLibrary()` needs no change, and a token stays pinned to its library even if
  the user switches library in the SPA mid-run. `last_used_at` updates best-effort and never fails
  a request.
- `scope = 'read'` rejects every non-GET with 403.
- PAT auth is **refused** on `/api/me/tokens` and `/api/admin/*`: a token cannot mint another token
  or reach sysadmin surface.
- `GET`/`POST /api/me/tokens`, `DELETE /api/me/tokens/:id` on the `authed` group (token management
  is user-level, not library-scoped). Secret returned once, on create. Create and revoke are
  audited. The secret and its hash are never logged.

### Stage 2 — Token management in the SPA

`web/src/components/settings/ApiTokensSection.tsx`, mirroring `LibraryMembersSection` — list,
create with label + scope + optional expiry, copy-once secret, revoke. This is the only way to mint
the credential, so it cannot be deferred.

### Stage 3 — `internal/toon` and the render layer

- Emit-only TOON encoder: tabular arrays `rows[2]{a,b}:`, primitive arrays `tags[3]: a,b,c`,
  key-value objects, `[]` for empty, and the quoting rules (quote if empty, number-like,
  `true`/`false`/`null`, leading `-` or `#`, or containing `: " \ [ ] { }` or the delimiter). No
  decoder — nothing in damson reads TOON.
- Then the shared render layer: TOON/JSON switch, `--fields` projection and validation, truncation
  with the char-count suffix, `help[]` emission, and the `error:` envelope with its exit-code
  mapping.
- Pure Go, no I/O, no gin. The whole AXI contract lives here and is table-testable.

### Stage 4 — `cmd/dmsn` skeleton and auth

- Subcommand dispatch on stdlib `flag`. Config at `os.UserConfigDir()/damson/config.json` mode
  0600, overridden by `--server` / `--token` / `DAMSON_SERVER` / `DAMSON_TOKEN`.
- HTTP client with bearer attachment, timeout, and status → `code` mapping.
- `login` (verifies via `GET /api/me`, never echoes the token), `logout`, `whoami`, `version`, and
  `--help` on everything.

### Stage 5 — Home view and `GET /api/overview`

The endpoint first — library-scoped, five counts plus a recent-import tail — then the
bare-invocation view: resolved binary path with `~`, one-line description, counts, recent imports,
`help[]`.

### Stage 6 — Read commands

`assets`, `asset <id>`, `tags`, `collections`, `collection <id>`, `imports`. Every filter maps to an
existing query param; pagination, aggregates, empty states and contextual `help[]` per command.

### Stage 7 — Upload

**Server first:** `POST /api/imports/preflight` in its name-only form, matching all entries against
a single library read (`MatchAssetByName` currently reads every asset in the library per call, so
the batch endpoint must hoist that read out of the loop), entry count capped. Plus
`max_upload_bytes` exposed read-only on `GET /api/settings` — it currently lives only behind the
sysadmin route, so a member's CLI cannot pre-check a large folder and only learns via 413 after
transferring it.

**Then the command:** `upload <path>…` with the required `--as` for directories, client-side zip,
`--skip-existing`, `--asset-id`, `--store-version`, `--concurrency 2`, `--dry-run` and `--wait`
(polling `GET /api/imports/:id` to a terminal stage). Per-file failure is logged and skipped rather
than fatal; a summary line prints and the exit code is 1 if anything failed. A 413 is reported as an
over-cap error, not a generic failure. The CLI honours `TMPDIR`, checks free space before zipping,
and fails with `code: no_space` rather than starting a doomed upload.

### Stage 8 — Mutations, build, agent install, docs

- `asset edit|review|unreview|rm|tag|untag`, `tag new|rm`, `collection new|edit|rm|add|remove`,
  `bulk …`, `import retry` — idempotent where the API allows, `--yes` on destructive verbs,
  `changed` / `affected` reported.
- `task build:cli` only. **No cross-compilation matrix, no Woodpecker step, no GitHub release
  artefacts** — deliberate, see Resolved questions.
- `dmsn setup` writing the Claude Code skill (`~/.claude/skills/damson/SKILL.md`, or the project
  directory under `--project`) and an optional SessionStart hook that runs the home view.
  Idempotent, prints every path it touched.
- Docs: a CLI section in `architecture.md`, a `progress.md` entry, and amending
  `2026-08-01-unity-local-cache-import.md` — drop its stages 1 and 4, narrow its preflight to the
  path-and-size half, renumber its migration to `021`, and depend on this spec.

### Testing

Stages 1–2, 5 and 7's server half sit in the existing Postgres-backed Go tier (`newTestHandler`) and
Vitest. Stage 3 is pure table tests. The CLI stages test against an `httptest` server, with
golden-output fixtures pinning the TOON shape. The CLI decodes into its own small structs rather
than importing `internal/handlers/api`, which would drag gin into the client binary — the drift risk
is real and the golden fixtures, captured from handler tests, are the guard.

## Reuse

Found by reading the tree at `ae3af73`, not assumed.

- **`POST /api/imports` already accepts `.zip`** as `packageKindZip` → `extract.ZipExtractor`, which
  writes `asset_files` with relative paths, picks a cover, thumbnails and enqueues previews. This is
  what makes folder-as-one-asset a client-side concern.
- **`asset_id` + `store_version` form fields** on the same endpoint already exist, with
  duplicate-`store_version` conflict detection — `--asset-id` is a pass-through.
- **`POST /api/assets/bulk`** covers `delete`, `review`, `unreview`, `add_tag`, `remove_tag`,
  `add_to_collection`, `set_licence` — 1000-asset cap, one transaction, audited. Every `bulk`
  subcommand is a thin wrapper.
- **`tags.Attach`** resolves hierarchical paths and creates missing ancestors; tags are
  `unique(library_id, path)`, so `asset tag` is naturally idempotent.
- **`assetMetadataFieldsPatch`** (from the 2026-07-31 slice) already covers all 13 storefront fields
  with "absent leaves alone, empty string clears to NULL" — exactly the semantics `--clear` needs.
- **`parseAssetFilters`** already accepts every filter the `assets` command exposes, and the handler
  already returns `total`.
- **`imports.MatchAssetByName`** and its normalised `titlesMatch` back the existing
  `suggested_match`; preflight reuses them.

Searched and absent: `internal/auth` has exactly two impls, both human-interactive — no API-key
mechanism, no `api_tokens` table, no long-lived credential of any kind. No TOON encoder in the tree
and none in `go.mod`. `cmd/` holds only `server` and `e2e-server`, two `main`s with no shared flag
or config plumbing to borrow, and no CLI framework in `go.mod`.

## Resolved questions

Settled during alignment on 2026-08-01. Not to be relitigated.

- **Binary name — `dmsn`.** An agent types it on every call; 4 characters against 9 is a measurable
  slice of the budget principle 1 protects, and principle 8's home view means nobody has to
  recognise the name from a package list. No `damsonctl` alias. The server binary keeps `damson`.
- **Directory upload — `--as` is required.** No default, no prompt: exit 2 with both concrete
  commands in `help[]`. Costs an agent one extra turn and never silently does the wrong thing with
  a multi-gigabyte tree.
- **Folder-as-one-asset — client-side zip**, reusing `ZipExtractor` whole. And
  `max_upload_bytes` becomes read-only on `GET /api/settings` so `--dry-run` can be honest.
- **Token scopes — `read` / `write`**, one column, default `write`. Means a token handed to an agent
  can provably not destroy anything.
- **`GET /api/overview` is added** rather than composing the home view from five existing requests.
- **No distribution plumbing.** `task build:cli` and `dmsn setup`, nothing else — explicitly no
  Woodpecker step and no GitHub release artefacts. Accepted consequence: the binary exists only
  where someone builds it, so `setup` is doing principle 7's discovery work without an install
  story behind it.
- **`--skip-existing` belongs in this spec**, not deferred to the Unity slice, and brings the
  name-only half of `POST /api/imports/preflight` with it.

## Out of scope

- Unity cache scanning, and the `already_imported` / `updated` precision of preflight — both stay
  in `2026-08-01-unity-local-cache-import.md`.
- Any release or distribution plumbing.
- Resumable or chunked uploads.
- Named profiles or multi-server contexts. One server, one token, per config file.
- Download and export commands. This slice is ingest and curate.
- Projects, pins, licences, previews, merge, subset — reachable via the API, not wrapped yet. Added
  on demand once the render layer exists.
- An MCP server.
- Shell completions, man pages, a Homebrew tap.
